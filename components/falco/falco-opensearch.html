Falco → OpenSearch Link

Routes Falco runtime security events to OpenSearch via Falcosidekick, and enables SIEM resources (index template, dashboard, alerting) on the OpenSearch side.

What This Link Does

On the Falco side:

  • Enables Falcosidekick's Elasticsearch/OpenSearch output
  • Configures the OpenSearch endpoint (internal svc or external remote_host)
  • Sets authentication with admin_password
  • Sets index name to falco with batching (5MB batch, 1s flush)
  • Enables JSON output format on Falco (required for structured forwarding)
  • Enables HTTP output to Falcosidekick

On the OpenSearch side (falco-opensearch inbound link):

  • Creates Falco index template (index-template-falco.json)
  • Creates Falco alerting monitor (alerting-falco.json) for Critical/Emergency/Alert events
  • Creates Falco dashboard (dashboards-falco.ndjson) in OpenSearch Dashboards
  • Applies PCI DSS ISM retention policy to falco-* indices

Cross-Stack (External) OpenSearch Support

Falco can export to an OpenSearch instance running in a different stack or cluster. The template automatically detects whether the target is local or external.

Scenario Helm Value: hostport Port
Same stack (is_external: false) https://{name}.{namespace}.svc.cluster.local 9200
External stack (is_external: true) https://{remote_host} 443

remote_host: The FQDN or IP of the external OpenSearch endpoint. Typically an APISIX route or load balancer that proxies to the remote OpenSearch cluster. Set as an attribute on the OpenSearch component. Both scenarios use checkcert: false (TLS skip verify).

OpenSearch Component Attributes Used

Attribute Source Usage in Falco Helm Values
namespace REQ __opensearch.component.attributes.namespace Internal endpoint construction: {name}.{ns}.svc.cluster.local:9200
admin_password REQ __opensearch.component.attributes.admin_password Falcosidekick elasticsearch.password config
remote_host __opensearch.attributes.remote_host External endpoint FQDN (only when is_external: true)

Helm Values Generated (Falcosidekick Output)

falcosidekick:
  enabled: true
  replicaCount: 2
  config:
    customfields: "stacktic_system:{system_name},stacktic_collector:falco"
    elasticsearch:
      # Internal (same stack):
      hostport: "https://{name}.{namespace}.svc.cluster.local:9200"
      # External (cross-stack):
      hostport: "https://{remote_host}:443"

      index: "falco"
      type: "_doc"
      minimumpriority: ""
      suffix: "daily"
      username: "admin"
      password: "{admin_password}"
      checkcert: false
      batching:
        enabled: true
        batchsize: 5242880    # 5MB
        flushinterval: 1000   # 1s
      flattenfields: false
      createindextemplate: false
      numberofshards: 3
      numberofreplicas: 1

Custom Fields for Multi-Stack Filtering

Falcosidekick injects custom fields into every event. These are critical for multi-stack SIEM dashboards:

Field Value Purpose
stacktic_system {configuration.system_name} Identifies which stack generated the event (used for cross-stack dashboard filtering)
stacktic_collector falco Identifies the source type (falco vs opa vs trivy etc.)

What Gets Created on OpenSearch Side

When OpenSearch detects the falco-opensearch inbound link AND siem attribute is "true":

Resource File Description
Index Template siem/index-template-falco.json Mapping for falco-* index pattern
Alerting Monitor siem/alerting-falco.json falco-critical-events monitor searching for Critical/Emergency/Alert priority
Dashboard siem/dashboards-falco.ndjson OpenSearch Dashboards saved objects (index pattern + visualizations + dashboard)
ISM Policy siem/ism-policy.json PCI DSS retention policy applied to falco-* indices

Falco vs OPA Export Architecture

  • Falco: Single link (falco-opensearch). Falcosidekick has native OpenSearch output — no sidecar needed.
  • OPA: Two links required (opa-otel + opa-opensearch). Gatekeeper has no native OpenSearch output — needs OTEL collector sidecar.

Multi-Port Networking & APISIX Routing

The ports attribute supports multiple ports (one per line). Each port follows the format: name:port:protocol[:stream]

Format Example Routing Type APISIX Behavior
name:port:protocol http:8000:TCP L7 HTTP Hostname-based route + TLS + plugins
name:port:protocol:stream agent:50000:TCP:stream L4 Stream Dedicated port on APISIX LB (no TLS/hostname)

APISIX link attribute: Set route_all: true on the apisix-image_base link to route ALL ports. Without it, only the first port gets an L7 route.

Note: L4 stream ports must be globally unique across all image_base components linked to the same APISIX instance. All ports (L7 + L4) are exposed in the K8s Service regardless of APISIX routing.

Routing Table (Multi-Domain Multi-Protocol)

Set routing_table on the apisix-image_base link to route multiple custom domains to different ports. This replaces subdomain and route_all when present. Each domain gets its own TLS certificate.

Format Example Behavior
domain mail.tenant2.ch Routes ALL ports (L7 HTTP + L4 stream SNI) for this domain
domain:port1,port2 webmail.tenant2.ch:webmail Routes only named ports (names from ports attribute)
Example: IceWarp multi-tenant setup

Component ports:

webmail:443:TCP
pop3:995:TCP:stream
imap:993:TCP:stream

Link routing_table (on apisix-image_base link):

mail.tenant2.ch:webmail,pop3,imap
webmail.tenant2.ch:webmail

Result:

  • mail.tenant2.ch → HTTPS (443) + POP3S SNI (995) + IMAPS SNI (993)
  • webmail.tenant2.ch → HTTPS (443) only
  • Each domain gets its own ApisixTls + cert-manager Certificate
  • Stream ports get tls: true in APISIX for SNI matching
Note: Port names in routing_table must match names from the ports attribute. Domains that are subdomains of the stack domain use the wildcard cert; custom domains get dedicated cert-manager Certificates.

Init Container (startup_commands) - Click to expand

When startup_commands is set, an init container runs the same image before the main app starts:

  • Commands written to startup.sh ConfigMap
  • Mounted at /startup/startup.sh
  • Shares volumes with main container (PVC, writable dirs)
  • Main app waits for init to complete successfully
startup_commands: |
  python manage.py migrate
  python manage.py collectstatic --noinput

Sub-Components (Multi-Image Deployment)

Add image_base_container sub-components to deploy multiple images in the same namespace under a single parent component. Each sub-component generates its own Deployment + Service + optional PVC.

Sub-Component Attribute Example Description
image_version REQ ghcr.io/mailu/admin:2024.06 Container image for this sub-component
ports REQ http:8080:TCP Same format as parent: name:port:protocol
replicas 1 Falls back to parent replicas if not set
pvc / mount_path / storage_size true / /data / 5Gi Optional persistent storage per sub-component
cpu/mem request/limit 100m / 128Mi Falls back to parent resources if not set

How it works: All sub-components share the parent's namespace, ServiceAccount, and cloud.env secret (envFrom). Each gets a separate Deployment named {parent}-{sub-component-name} and matching Service.

Generated file: container.yaml — only rendered when at least one image_base_container sub-component exists.

Env Mapping (Link Attribute)

Add env_mapping on any link (to or from) to create env var aliases. Solves naming mismatches between linked services without duplicating values in cloud.env.

Format Example Generated K8s
NEW_VAR:EXISTING_VAR DB_HOST:MYSQL_HOST - name: DB_HOST
  value: "$(MYSQL_HOST)"

One mapping per line. Kubernetes resolves $(EXISTING_VAR) from the envFrom secret at pod startup. Applied to both parent and sub-component containers.

Custom DNS Resolver (Rare Use Case) - Click to expand

For apps requiring custom DNS (e.g., DNSSEC validation). Set on sub-component or parent component.

dns_resolver Custom nameserver IP (e.g., unbound ClusterIP). Set on sub-component or parent.
cluster_dns Cluster DNS IP as fallback nameserver. Set on parent component only.

When dns_resolver is set: dnsPolicy: "None" + custom nameservers + cluster search domains. When empty: no effect.

Common Issues
  • user_id must match image USER
  • Python OTEL needs pythonpath
  • read_only_fs needs writable dirs
Production Checklist
  • All security_features enabled
  • user_id != 0 (non-root)
  • framework_type set correctly

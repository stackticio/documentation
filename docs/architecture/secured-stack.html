Example: a secured marketplace

Worked stack
Two production applications and every security layer turned on

This is a marketplace stack the Stacktic team runs as its security reference: a catalog API, a shop front end, an AI assistant, and around them every security component the catalog offers. Every control below is a component, a sub-component, a link or an attribute on its diagram.

Security, layer by layer​

At the edge​

ControlOn the diagramWhat it does here
Rate limitsrate_limiting and rate_limit_count on seven of the eight route links (not on Grafana)APISIX limit-count per client address, counted on each gateway replica
Web application firewallCrowdSec waf sub-component, linked waf-external_source_code to both applications; apisix-crowdsecCrowdSec's AppSec engine (Coraza with the OWASP Core Rule Set, virtual patches, generic rules) checks every request to both applications. The profile runs in detect: matches raise alerts, nothing is blocked yet. With passthrough, an unreachable WAF lets requests through

Log sources for CrowdSecapisix-crowdsec, crowdsec-suricata; collections suricata, base-http-scenarios, http-cveThe agent on every node reads the gateway access log and Suricata's events

Secrets​

external-secrets links external_secrets-openbao: a seed Job writes the stack's secrets into OpenBao, and External Secrets syncs them into the namespaces that use them. openbao-swbucket takes Raft snapshots of OpenBao into a bucket on a schedule. See Identity and secrets.

What the design deliberately leaves out​

These are choices on this diagram, not gaps in the platform:

  • The application routes do not use gateway login; the applications authenticate their own users.
  • The WAF runs in detect. Switching the profile's waf_mode to block turns matches into refusals once the alerts have been reviewed.
  • Falco has no OpenSearch link, so its events are not in the SIEM.

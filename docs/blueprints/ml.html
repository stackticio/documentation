Machine learning

Blueprint
Draw the loop, not the plumbing

An experiment is where runs are logged. A registered model is where trained versions live. A job trains or applies one. Buckets hold data, labels and weights. The links between them generate every address, name, credential, GPU placement and network rule.

The shape​

What each piece is​

PieceRole
Experiment tracking and model registryEvery run, every metric, every artifact, every version
A relational databaseThe registry's backend store, and pipeline metadata
Object storage bucketsArtifacts, curated data, labels, weights, run logs
An orchestratorRuns training and apply jobs on demand, on GPU when asked
Your trainer imageYour own code, built by the platform from your repository
A gatewayThe tracking interface's address, and a login in front of it when you want one
MetricsScrapes the tracking server's own health — not the metrics your runs log
A decision recordThe signature a job reads before it starts, and that a promotion follows

Without a database and a bucket, the registry falls back to local storage. That fallback is for development only, and the platform says so rather than letting you discover it.

The two sub-components that carry the loop​

Sub-componentSideWho links to itWhat the link generates
ExperimentWriteTrainers — a job, an asset, or your own code componentThe tracking address and the experiment name, so the run lands in the right place
Registered modelReadConsumers — an apply job or a serving componentThe model address, its name and its alias

A sub-component-to-sub-component link binds them: runs logged here become versions there. A trainer linked only to the experiment still learns which model to register to, because the binding is read from the experiment's own record.

Both are created for you when the registry deploys, idempotently, with their tags and descriptions.

Promotion is moving one alias​

Consumers load the model by alias, not by version number. Promotion is a person moving the alias to another version.

No rebuild. No redeploy. The next run loads the new champion, and rolling back is moving the alias back.

Two deliberate human moments​

BeforeStarting a run

A training run can cost real money. A job can be made to refuse to start until a decision record carries a signature.

AfterPromoting a version

A promotion changes what your users get. It can be made to follow a signed decision rather than a chat message.

Everything between those two moments is automatic. Both signatures are records, and an AI may propose them but never sign them.

→ Reviews and approvals

GPU, queueing and cost​

GPU placement comes from the job's attributes — the node selection, the sharing mode, the memory fraction per model. Heavy periodic work can be admitted through a queue rather than competing with production workloads, with priority expressed as an attribute.

Because all of it is on the graph, the expensive parts of an ML platform are visible in a diff and roll back with everything else.

Compliance automation

Compliance
Compliance is not a document. It is a measurement with a signature on it.

Most of what a framework asks for is already a property of how the system was built. The rest is a position a person has to take. Stacktic automates the first, records the second, and makes both checkable.

Three layers, and none of them is a spreadsheet​

1 · GeneratedThe control is built in

Segmentation, least-privilege access, encrypted credentials, TLS everywhere, admission policy, audit logging and backup are produced from the graph — so the control exists because of how the system was generated, not because someone configured it afterwards.

2 · MeasuredThe control is proven

Every control is validated against the running cluster with real command evidence: what was queried, what came back, and what that means. Not a checkbox, and not a metadata inference.

3 · PositionedThe gap is owned

Where a control cannot be met automatically, a named person records a position — confirmed gap, compensating control, not applicable, or accepted risk with an expiry date. That position is the audit-defensible artefact.

What "evidence" means here​

Every control returns the command that ran, its output, and the result derived from it.

{
  "id": "A.5.2",
  "title": "Information security roles and responsibilities",
  "runtime_status": "In Place",
  "finding": "RBAC verified: 23 role bindings, compliance score 85%",
  "evidence": [{
    "command": "kubectl get rolebindings --all-namespaces + declared vs actual",
    "output": "Expected: 30 RBAC resources, Found: 23, Missing: 7 ...",
    "result": "RBAC score=85% expected=30 found=23 missing=7"
  }]
}

An auditor can re-run the command. That is the point.

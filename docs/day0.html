Day 0–1 — design and generate

Day 0–1
Vibe coding, inside a framework

AI is very good at writing the application. It is structurally unable to write the relations around it — because those relations were never in its context, and because compliance, security and proof are not things a prompt can improvise.

Visual explainer · 10 slidesAutomation, not autocomplete

The same prompt, run three times, builds three different systems — and then cannot operate any of them. Why building is the easy half.

↗

The problem with how this is done today​

People vibe code. The code arrives quickly and it usually works. What arrives with it is the part nobody looks at until it matters:

What the model could not see
  • Which namespaces are now allowed to talk to each other, and which should not be.
  • Where the credential came from, who else holds it, and whether it is encrypted at rest.
  • Whether the new endpoint is behind the gateway, behind a login, or simply on the internet.
  • What the backup covers now, and whether it can be proven to hold data.
  • Which regulatory control this just moved, and what the evidence for it is.
What Stacktic does instead
  • The relation is declared, so the policy is generated from it — both directions.
  • Credentials are generated per instance and encrypted in the repository.
  • Exposure is a link. Drawing it produces the route, the TLS and the login.
  • Backup is a link too, and the agent reports whether it actually holds bytes.
  • Controls are measured from the running cluster and recorded with an attestation.

What "production-grade" means here, concretely​

The output of a build is not a starting point you then harden. It is the hardened form.

DimensionGenerated by default
IsolationNamespace-level network policies derived from the links — nothing that is not declared is permitted
AccessCross-namespace RBAC scoped to what each link actually needs
SecretsGenerated per instance, encrypted in the repository, optionally sourced from a secret store instead
ExposureGateway routes with TLS certificates issued and renewed automatically
IdentityOIDC clients and redirect URIs produced from the links, not hand-maintained
AdmissionPolicy baseline planned against your actual topology, with the carve-outs that topology needs
ScalingAutoscaling driven by real signals — queue depth, query results, inference load
RecoveryBackup schedules and retention as attributes of the relationship they protect
ObservabilityScrape targets, dashboards, alert rules and log collection wired from the links
EvidenceA validation surface that can prove each of the above, run by run

Then it is validated, before you trust it​

Generation is a claim. The stack agent turns it into a measurement: every declared relationship proven layer by layer, scored security scans, compliance controls with real command output as evidence, and a hash chain so a report names the exact system state it judged.

This is the part that vibe coding cannot produce on its own, and it is the reason an AI can be allowed to operate the result.

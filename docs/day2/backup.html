Backup and recovery

Recover
A backup that reports success and holds nothing

That is the failure this exists to catch. Backup tooling routinely reaches a completed state whether it copied gigabytes or nothing at all — and nobody finds out until the day it matters.

Discovered from the graph​

Protection is not configured twice. A link drawn between a database and a storage target is an intent; the agent reports whether the cluster actually honours it. Because the mechanisms are discovered from the metadata structure, this works on any stack without per-stack configuration.

The verdict that matters​

VerdictMeaning
PROTECTEDBytes were captured and verified
COMPLETED_NO_DATAThe dangerous one. The backup reports success and holds zero volume data
NEVER_RANConfigured, never executed
NOT_PROTECTEDThe mechanism is missing or misconfigured
INCONCLUSIVECould not be verified — a permission denial or an absent resource type. Not the same as unprotected

Only the deep scan mode can prove that data exists; the fast mode reports structure. A score of null means the stack has no backup wiring at all — which is "nothing is configured", not zero percent.

What it is

Restore points are a catalogue, not a list​

A restore should be chosen from something. The agent produces a dated catalogue of every point you could restore from, grouped by day, each one carrying what it costs to pick it: when it was taken, how many bytes it actually holds, when it expires, whether a human has certified it, and — when it cannot be used — the reason.

A point is not selectable when it partially failed, when it captured zero bytes, when it has expired, or when its mechanism cannot target a specific artefact. The same rule the scan enforces is applied at the moment of choosing: a backup that cannot be proven is never offered as a restore source.

Where a mechanism has a limitation, it is stated on the point rather than hidden. Artefacts are listed so you can see what exists, marked unusable with the reason.

Recovery horizon is an attribute of the relationship​

Schedule and retention live on the link between the data and its storage target, not in a separate backup configuration. The cadence and the recovery horizon are therefore part of the graph: versioned with it, duplicated into staging with it, visible in a diff.

Where a horizon was never set explicitly, the scan says so, so an inherited default is visible as an inherited default.

Day-2 control is opt-in and layered​

Reading and rendering manifests always works. Applying anything requires every one of the following:

API authentication

The agent's key, when one is set.

An explicit attribute on the component

Write operations are off by default. In-place restore needs a second attribute on top.

A rendered manifest

The exact YAML is produced and server-side dry-run first. A confirmation token embeds the resolved target, so the manifest step cannot be skipped.

An exact confirmation token

Naming the subject and, for a restore, where the data lands.

A typed human phrase — for restores only

Case-sensitive and exact. Enforced by the API, not only by the interface, so it cannot be pre-filled by a caller acting on someone's behalf. Taking a backup needs no phrase.

An admitted dry run

Before anything is applied for real.

Restores default to a scratch namespace; the live namespace is untouched unless you have explicitly enabled in-place restore. Every attempt — including every refusal — is recorded in the agent's own write audit trail.

Certification and pinning​

A restore point can be certified by a named person, and that certification is part of its history. A point can also be pinned: a new backup taken with a long retention and a label, which is the only honest way to keep a checkpoint when retention is time-based and existing artefacts cannot be exempted from it.

Continuously replicating mechanisms​

Some mechanisms do not have runs — off-site replication, write-ahead archiving. They have no schedule, no retention window and no per-run byte count; they are healthy when their workload is ready. The interface reads this from the mechanism's own declared capabilities, so these are shown correctly without a special case, and a new mechanism needs no interface change.

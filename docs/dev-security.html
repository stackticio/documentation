Development security

From commit to evidence
Security checks you ask for, not pipelines you maintain

A developer adds a link or flips an attribute on the design. The build Job that is generated from it carries the gates; the scanner component that is generated from it runs the dynamic tests; the stack agent collects every verdict and maps it to the control an auditor will ask about. Nothing here is a CI script somebody wrote once and nobody dares to touch.

Three facts hold the chain together:

  • A gate is an attribute or a link, not a pipeline file. build_gate: enforce on an application is the whole configuration; the generated build Job carries the init container. A nuclei-apisix link is the scan of every route that gateway publishes.
  • Every verdict is written in one place. The build Job prints a verdict line per gate; the DAST Job pushes its run to the agent; the agent reads both and keeps them as versioned, hash-chained records, long after the Job itself is gone.
  • The record is what the auditor sees. The PCI DSS and ISO 27001 scans do not count components; they read these records. A gate switched on but never run is "Not In Place", by design.

Asking for it​

The design tools of the MCP — and the platform UI — are the only interface. There is nothing to write by hand.

“Add code scanning to my app”

The assistant adds a sonarqube component if the stack has none and a sonarqube-<app> link with scan_enabled — the scan runs after each build and reports. With enforce_quality_gate on the same link, the analysis moves into the build Job, in front of the builder, and a failed quality gate pushes nothing. For your own rules it sets sast_gate and sast_rules on the application instead: no server, no project, one attribute.

“Add DAST”

The assistant adds a nuclei component, links it nuclei-stack_agent (so runs become evidence) and nuclei-apisix (every published route, weekly), and for your own applications a nuclei-<app> link with a fuzzing level and the OpenAPI document. The agent's DAST scan proposes exactly these links when they are missing — as machine-readable actions the assistant can apply.

Build and watch

stacktic_auto_layout, then stacktic_set_system, then a build. Argo CD applies the deploy directories; the build directory of the application runs the gates on its next build. The agent's tabs show the first verdicts without anything else being configured.

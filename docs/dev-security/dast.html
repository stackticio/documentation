DAST as a design fact

What the stack exposes
A scan you can see on the diagram

The nuclei component scans nothing by itself. Draw a link from it to the gateway and every route that gateway publishes is swept on a schedule. Draw a link to one of your applications and that application gets a deep contract: fuzzing, its OpenAPI document, authentication. Delete the link and the scan is gone. The design is the scope.

The three links​

LinkWhat it scansAttributes
nuclei-apisixEvery route the gateway publishes — the subdomain and additional_domain of each apisix-<type> link, on the stack's domain — unauthenticated, as the outside sees itprofile, severity, schedule, rate_limit
nuclei-<app> (external_source_code, image_base, fastapi, fastmcp)That one application: its public route, or its in-cluster Service when it has nonethe four above, plus dast (off · low · medium · high), openapi_path, auth (none · oidc_client)
nuclei-stack_agentNothing — every run is pushed to the agent, and the agent gains a Role to start a run on demand—

profile names one of nuclei's own template profiles (compliance, pentest, recommended, kev, cves, misconfigurations, default-login) or automatic (technology detection chooses the tags). dast adds nuclei's fuzzing templates — SQL, command and template injection, XSS, SSRF, file inclusion, XXE, redirects — which send attack payloads into the application; keep it to non-production contracts or a schedule a person approved. openapi_path is what makes fuzzing real: a bare URL carries no parameters; an OpenAPI document gives every endpoint and parameter (FastAPI serves /openapi.json, springdoc /v3/api-docs). auth: oidc_client takes the client credentials from the application's own gateway link and scans as that client.

Component attributes: version (nuclei release, also the image tag), templates_version (the template corpus, pinned), exclude_tags, custom_templates (your own templates — write nuclei's BaseURL as ${BaseURL}), internal_sweep and internal_schedule (in-cluster services of every other component, not link-bound).

What a run records, honestly​

Each CronJob runs one contract and pushes one record. The record says:

  • every target with its probe result — a route that answers 502 is listed and not scanned, and a contract with nothing reachable is no_targets, never "clean";
  • every step (profile, dast, custom) with whether it finished, how many templates nuclei loaded, how long it took — a step cut off by its time budget is completed: false;
  • out-of-band testing is off (no interactsh server), and the record says which templates that excludes;
  • findings deduplicated per host and template, with CVE/CWE/CVSS, references and the request and response that matched.

What the agent shows​

DAST Coverage (/dast_scan) answers three questions in order: is every public route under a contract; did every contract actually run; what did the runs find. Below them: every public route with the contracts covering it, every contract with its newest run (status, steps, templates, top findings), and a findings list where each gap carries the action that closes it — add_link nuclei-apisix for an unscanned gateway, add_link nuclei-<type> with the recommended deep contract for an application that is only swept, set_attribute openapi_path for fuzzing without parameters, run for a contract that never ran. Full starts every contract's Job through the Role the agent link rendered and waits.

The Penetration Test reads the same runs for its signature checks (SQLi, XSS, SSRF, file inclusion, default logins, exposed panels, TLS): a route with no contract makes those checks SKIPPED, a cut-off run makes them INCONCLUSIVE, a match makes them FAIL — never PASS by absence.

Two things to know before trusting a finding​

  • Redirects are not followed. An "unauthenticated access" template requires a 200 with page markers; a protected service answers 302 to its login page, and following it would produce a false HIGH from the login page itself. The run uses nuclei's default; templates that need redirects declare it.
  • A sweep has a budget. The compliance profile loads several thousand templates; against ten routes at the default rate it needs the better part of an hour. The step budget is sized for a weekly sweep; a cut-off step is reported, not hidden.

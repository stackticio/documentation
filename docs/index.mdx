<Hero eyebrow="Automation platform" title={<>Graph the system.<br/>Automate everything.</>}>
Stacktic turns every layer of a complex application into a connected, machine-readable
graph — giving AI the context to architect, secure, deploy, operate and validate the
entire system autonomously.
</Hero>

Your AI writes the application. Stacktic automates everything under it: the topology, the
operations, the security and the compliance — and keeps all of it correct with every
change.

<Explainer href="/explainers/stacktic-intro.html" title="Graph the system. Automate everything." slides="9">
  The whole idea in nine slides: what one prompt actually moves, why the relations are the
  hard part, and what it means for AI to work inside a framework.
</Explainer>

## The gap AI cannot close on its own

An application is not the code. It is the code plus the database it talks to, the secret
that carries the password, the route that exposes it, the policy that constrains it, the
network rule that lets the two namespaces speak, the backup that can prove the data
survived, and the evidence an auditor will ask for.

<Split>
  <Side tone="problem" head="Vibe coding as it is today">
    <ul>
      <li>The model edits the code it was pointed at.</li>
      <li>The relations around that code — data, access, policy, evidence — are never in its context.</li>
      <li>Compliance cannot be improvised, and security is not tuned by a prompt.</li>
      <li>Nothing verifies the result. Production finds the gaps for you — in an outage, an audit, or a bill.</li>
    </ul>
  </Side>
  <Side tone="answer" head="Vibe coding inside a framework">
    <ul>
      <li>Every relation is declared, so nothing is guessed.</li>
      <li>Security and compliance defaults are generated, not remembered.</li>
      <li>The whole stack is produced as production-grade, autoscaled Kubernetes.</li>
      <li>The result is validated, attested and hash-chained before anyone trusts it.</li>
    </ul>
  </Side>
</Split>

## What the graph contains

A stack is a directed graph. Components are the nodes, links are the edges, and
sub-components are the resources a component owns — a database, a bucket, a topic, a
queue, an OIDC client, a model. Every edge generates real configuration: environment
variables, secrets, gateway routes, network policies, RBAC, scrape targets, backup jobs.

## The two repositories you own

Everything you work with lives in two places, and both are yours.

| Repository | What it holds | Who writes it |
|---|---|---|
| **Your application repository** | Your source code, one folder or one repo per application component | You and your AI |
| **Your stack repository** | The generated GitOps tree: manifests, overlays, policies, build pipelines, docs, and the `stack-metadata.yaml` that describes the graph | Stacktic, on every build |

The templates that do the generating are part of the platform. You consume their output;
you never have to read them.

## Before you write one

Most needs fit the existing catalog: an attribute, a free-form configuration field, a link
that already exists. The MCP's `platform_gap` checks exactly that — whether the need is
really missing, and what existing flexibility covers it — and reports a genuine gap to the
platform team.

## What a component type defines

Under **Catalog → Components**, a new type has:

| Part | What you set |
|---|---|
| **Identity** | A technical id — which is also the name of the type's folder in the template repository — a label, a description, the description shown on the diagram, a group, a family, and a logo |
| **Attributes** | Each with its type, options, the pattern free text must match, and a default |
| **Links** | The component types it may connect to, and the attributes each link carries |
| **Sub-components** | The sub-component types it can own |
| **Guides** | Help text per attribute, shown in a *Guide* window on the design page |
| **Versions** | Several versions side by side, one marked as the default new designs get |
| **Template repository** | The git URL and branch of the template, and the credential that clones it |

The type then appears in your catalog next to Stacktic's, is offered on the design page, and
is validated like every other entry. Marking a type **ignored** keeps it drawable but stops
every build from rendering it.

:::note Personal access tokens are git credentials
The *Personal access tokens* under your profile are the credentials a component type uses
to clone its template repository — a user name and a password or token for your git host.
They are not tokens for the platform API.
:::

## Let the platform write the template

Tick **Source Code**, **Helm**, or both, and save. With **Helm** ticked, the form also asks
for the chart's repository, name, URL and values. The platform clones the template
repository, writes a template for the type, and commits it as `stackticbot`:

| Part | Contents |
|---|---|
| Every template | The variables file, and a generation hook that already detects every link and sub-component type you declared |
| **Source Code** | A workload, its RBAC, a resource patch, a clean-up job and an image-signature check, the registry secret, and an overlay |
| **Helm** | The values file, a script that renders the chart, an ingress, a namespace, a kustomization, and an overlay |

It is a starting point: open the repository and write what the type actually generates.

:::caution Untick both boxes once you edit the template
Every save with a box ticked deletes the type's folder in the template repository and writes
it again. Keep them ticked only while you are scaffolding.
:::

## Changing a type later

Saving a type notifies every system that uses it. Their designs show a synchronisation
notice, and programmatic changes to those systems are refused until it is acknowledged — so
nothing is built against a definition that moved underneath it.

<Hero eyebrow="The platform" title="Where the graph lives">
The MCP server is how an AI works with a stack. The platform is where the stack exists —
the canvas, the catalog, the versions, the collaborators, the live view and the history
you can return to.
</Hero>

## What it is

A system is drawn on a canvas: components, sub-components and links, each carrying
attributes from a version-pinned catalog. That drawing is the graph. Everything else in
Stacktic reads it, generates from it, measures against it or returns to an earlier version
of it.

## The three things it guarantees

<Steps>
  <Step title="The drawing is always valid against the catalog">
    Names are unique and well-formed, every component exists in the catalog at the version
    it claims, every attribute is one the catalog defines with a value the catalog allows,
    every sub-component sits under a parent that can own it, and every link is one the
    catalog permits between those two types. A drawing that violates any of this cannot be
    built through the API.
  </Step>
  <Step title="Every state is recoverable">
    Each save and each build is stored with its diagram. Nothing is lost by changing your
    mind.
  </Step>
  <Step title="Your edits to the generated repository survive">
    Files you asked the platform to leave alone stay yours, and a conflict stops a push
    rather than committing over your work.
  </Step>
</Steps>

LiveView

Watch
The design, coloured by its test results

LiveView shows the diagram you drew with each component coloured by the result of its tests against the running cluster. The tests come from a Test paper in the catalog, and the stack agent in your system runs them.

Opening it​

On the design page, click Switch Paper and choose a Test paper. A read-only copy of the drawing opens. Switch Paper again returns to the design.

LiveView needs a stack agent component in the design. The platform reaches the agent through two attributes of that component: agent_endpoint and api_key. Without a stack agent the page says so ("Stack Agent does not exist in your system!") instead of showing colours.

How a run works​

One request per component

The page sends each component's type, version and the name of the Test paper to the platform.

The catalog supplies the tests

The platform looks up the tests the catalog defines for that component type and version in that paper. A component with no tests there turns grey.

The stack agent runs them

Each test (its command, target, filter and severity) is sent to the stack agent. The agent runs it against the cluster, using the stack's metadata to find what the test targets, and posts the result back to the platform.

Results colour the drawing

Results reach the page over a live connection and colour the component as they arrive.

The tests run once when the paper opens. Run Tests clears the colours and runs them all again. Right-click a component to run only its tests, or to read its last results. Nothing re-runs on its own.

What the colours mean​

ColourMeaning
RedAt least one test of the component failed with severity critical
AmberAt least one failed with severity warning, and none with critical
GreenNo test failed. A failed test with severity info also leaves it green
GreyThe paper has no tests for this component type and version, or no result has arrived

A sub-component takes the colour of the component that owns it. Links are not coloured. A test that targets a component's links counts towards the component's colour.

Reading the results​

The results panel of a component has one tab per target: the component itself, its sub-components, its links to and from other components, its sub-components' links, and its attributes. Each tab shows how many results it holds and their worst severity. Each result shows passed, warning or failed, its target, its description and the steps it ran.

Where the tests come from​

Tests are catalog objects. Each belongs to one component type and version and to one Test paper, and is managed under Catalog → Tests. Because tests belong to types and not to your system, adding a component to a design brings its tests with it. A Test paper groups tests for one purpose, so the same drawing can be checked against different papers.

The stack agent also has its own validation, independent of papers. It proves every declared link layer by layer: wiring, secret, network, access and protocol. See Validation.

Why it is the same drawing​

The topology is declared rather than discovered. That is why the drawing you designed can show test results directly, with nothing to map, tag or keep in sync between a design tool and a monitoring tool.

<Hero eyebrow="Reference" title="Terms, defined once">
Most confusion about Stacktic is vocabulary. These are the words that carry a specific
meaning here.
</Hero>

| Term | Meaning |
|---|---|
| **Stack** | One system, as a graph. The unit of version, duplication and rollback |
| **Component** | One technology instance in a stack. Its type selects the generation logic |
| **Sub-component** | A resource a component owns — a database, bucket, topic, queue, client, model. A node in its own right |
| **Link** | A typed, directed edge. Named `sourceType-targetType`. Generates real configuration on both sides |
| **Attribute** | A value on a component, a sub-component or a link. The only place configuration lives |
| **Graph** | Components, sub-components, links and attributes together — the complete description of a system |
| **Stack metadata** | The graph written as data into your stack repository; what the agent measures against |
| **Build** | Regenerate the whole stack repository from the graph |
| **Push** | Regenerate only the files the changed attributes can affect |
| **Full push** | Commit the whole system from the background pre-render of your last save — a build without the rendering wait |
| **Impact map** | Per-component mapping from an attribute to the generated files it can affect. What makes a push small |
| **Generated branch** | The branch of the stack repository only the platform writes (`git_branch`, by convention `stacktic`). Rewritten by every build |
| **Build branch** | The branch the generated output is merged into (`build_branch`, usually `main`). Your edits and application code live here; deployments read it |
| **Merge** | The per-file three-way merge of the generated branch into the build branch, after a build with *Merge* ticked or a Save & Push |
| **Divergence list** | The files on your branch that differ from what the platform would write, with a choice per file: merge, overwrite or ignore |
| **API build** | A build started through the platform API, the MCP's included. It writes the generated branch and does not merge |
| **External component** | A copy of another system's component (`is_external`): it lives in another cluster, and nothing is rendered in its name |
| **Referenced component** | A placeholder for another system's component (`is_referenced`), rendered as local |
| **Cross-stack egress** | The network policy rule that opens a pod's connection to another stack's address, read from the link's address attribute |
| **Login from a link** | A gateway login built from the application's identity-client link, switched on by `apisix_oidc_enable` on its route |
| **Realm** | A separate user space in the identity provider: its own users, groups, sessions and rules. Extra realms are sub-components |
| **Identity provider** | An external OpenID Connect sign-in that Keycloak brokers, such as Microsoft Entra ID. A sub-component |
| **Hand-over** | What happens to a declared user who signs in through a provider: the local password is removed and the provider becomes the only way in |
| **WAF profile** | One CrowdSec AppSec configuration (`waf` sub-component) that a gateway route sends requests to before the application |
| **Firewall bouncer** | The CrowdSec DaemonSet that drops traffic from banned addresses on every node |
| **SIEM source** | A component whose `<source>-opensearch` link ships its events to OpenSearch, with an index template, dashboards and monitors |
| **Evidence tier** | For ISO 27001, the *Standard* floor of evidence and the *Strong* set on top of it; a passing control is graded with one of them |
| **Client profile** | The tool list the MCP server serves to a client: `full`, or `compact` for clients that cap their tools |
| **Overlay** | An environment's differences from the shared base |
| **Declared state** | Anything in the graph — components, links, attributes, system users, routes, policies |
| **Runtime data** | Anything an application wrote — a ticket, a file, a row. Not in the graph, and should not be |
| **Drift** | Runtime state that no declaration accounts for |
| **Section** | A catalog group of system-wide settings and of chosen component attributes, edited per system. Section values switch stack-wide behaviour such as air-gapped mode and network policies |
| **Paper** | A named sheet of the catalog: Rationale papers hold knowledge, Test papers hold validation tests |
| **Rationale** | The text on one cell for one paper — why it exists and what it does. Stored in the graph, shown as the Knowledge page of the design |
| **Stack agent** | The component that measures the running system against the graph |
| **Link validation** | Proving a declared edge layer by layer: wiring, secret, network, access, protocol |
| **Probe file** | A technology's own protocol check, shipped with its template and collected into the agent |
| **Scan** | A scored measurement of one dimension of the running system |
| **Finding** | One issue from a scan, with a stable identity, a first-seen date and evidence |
| **Delta** | The classified difference between a run and the previous run of the same type |
| **Attestation** | The hashes and context that fix what a run measured, and against which state |
| **Baseline** | A labelled run. Drift is measured from a baseline; change is measured from the previous run |
| **Review** | A named person's recorded position on a control or a link the automation could not pass |
| **Gate** | A record of human approval that something else waits on before it runs |
| **MCP** | Model Context Protocol — how an AI client talks to the platform |
| **Dispatcher** | An MCP tool taking an action enum, with a built-in help action |
| **Knowledge layer** | What the MCP reads to answer correctly — catalog, semantics, patterns, recipes, playbooks |
| **Recipe** | A declarative upgrade or migration procedure for a component |
| **Blueprint** | A recognisable arrangement of components and links. Not a special mode |

<Hero eyebrow="Kanso" title={<>One backlog.<br/>Agents and people, on the same record.</>}>
Kanso is a work-management system built for autonomous AI development. Your agents and
your team work the same backlog, through the same API, under the same permissions. Every
action, by a person or an agent, lands attributed in one history.
</Hero>

Once AI agents start working alongside a team, three questions decide whether you can trust
their work. **Who did this? Under whose authority? Who signed it off?** Kanso is built so
that every write answers all three, whether a person or an agent made it.

## What Kanso gives you

<Cards>
  <Card to="/kanso/agents/connect" kicker="Agents" title="Agents are users, not bots">
    An agent connects over MCP with a personal API token. The token is read-only by default,
    it always expires, and every write it makes shows its name.
  </Card>
  <Card to="/kanso/agents/human-answers" kicker="People" title="Ask a person, get data back">
    An agent asks a question on any ticket with a typed answer shape. The person answers on a

  </Card>
  <Card to="/kanso/agents/connect" kicker="Fleets" title="Work that does not collide">

    shows on the board, and a person can call their own agent off.
  </Card>
  <Card to="/kanso/work/projects-issues-fields" kicker="Work management" title="The tracker your team already needs">
    Custom fields, versioned workflows with guards, forms, boards, backlog and sprints, and
    JQL search.
  </Card>
  <Card to="/kanso/integrate/api" kicker="Integrate" title="One API for everything">
    The web interface, agents and your own services all use the same public API. Webhooks are
    signed, and apps run in a sandbox.
  </Card>
  <Card to="/kanso/migrate/jira-migration" kicker="Move from Jira" title="Assess first, then import">

    written.

## The ledger, not the orchestrator

Kanso never starts, dispatches or stops your agents. Your agents, in any MCP client, **pull**
work from the backlog. Kanso records what they claim, change and ask, and it notifies a
person when an agent needs one.

There is no LLM inside Kanso and it holds no model credentials. You choose the model and run
the agents, and Kanso keeps a record of every action.

## Start here

<Steps>
  <Step title="Install Kanso">
    One Helm command, with a built-in database for evaluation. See [Install](/kanso/run/install).
  </Step>
  <Step title="Connect an agent">
    Mint a token under **Security → Connect an agent** and paste the one command it shows into
    your MCP client. See [Connect an agent](/kanso/agents/connect).
  </Step>
  <Step title="Bring your work over">
    Point the importer at a Jira backup and read its assessment first. See
    [The Jira importer](/kanso/migrate/jira-import).
  </Step>
</Steps>

Falco Runtime Security

Kubernetes runtime threat detection via Falco. Deploys as a DaemonSet with kernel-level syscall monitoring (eBPF driver) to detect anomalous behavior, privilege escalation, and container escapes in real-time.

Architecture

Falco DaemonSet - One pod per node, kernel syscall monitoring via eBPF driver
Falcosidekick - Event forwarder (2 replicas), routes alerts to OpenSearch and other outputs
Metrics Endpoint - Prometheus metrics on port 8765 (/metrics)
Rules Engine - Evaluates syscall events against detection rules, outputs JSON alerts

Attributes

Attribute Example Description
namespace REQ falco Kubernetes namespace for all Falco resources
falco_driver modernEbpf Kernel driver type for syscall capture. Options: modernEbpf, ebpf, kmod → helm driver.kind
falco_sidekick true Enable/disable Falcosidekick deployment (event forwarder). When true or when __opensearch is linked, enables JSON output and HTTP output to sidekick
falco_priority warning Minimum alert priority level. Events below this are dropped → helm falco.priority

Links

Link Direction Generated Output
Prometheus → Falco Inbound Generates service-monitor.yaml - ServiceMonitor CR in Prometheus namespace, scrapes Falco /metrics on port 8765 (30s interval, 10s timeout)
Falco → OpenSearch Outbound Configures Falcosidekick to forward events to OpenSearch. Supports same-stack (internal svc) and cross-stack (external remote_host) endpoints. Index: falco. Also enables SIEM on OpenSearch side (index template, dashboard, alerting).

How Detection Works

Kernel level: eBPF probes capture syscalls from all containers on the node
Rules engine: Evaluates each syscall against Falco rules (built-in + custom)
Alert output: JSON events with priority, rule, output fields, container metadata
Forwarding: Falcosidekick receives events via HTTP and routes to configured outputs
Custom fields: Each event includes stacktic_system and stacktic_collector: "falco" for multi-stack filtering

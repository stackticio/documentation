OPA → OpenSearch Violation Export Link

Configures the OTEL sidecar to export OPA violations directly to OpenSearch, and tells OpenSearch to set up SIEM resources (index templates, dashboards, alerting).

What This Link Does

This link has two-sided effects:

On the OPA side (this template):

  • Switches the OTEL sidecar exporter from OTLP to OpenSearch
  • Configures the OpenSearch endpoint (internal or external) with authentication
  • Sets logs_index: opa so violations land in the opa-* index
  • Adds basicauth/opensearch extension with admin credentials

On the OpenSearch side (opa-opensearch inbound link):

  • Creates OPA index template (index-template-opa.json)
  • Creates OPA alerting monitor (alerting-opa.json) for violation events
  • Creates OPA dashboard (dashboards-opa.ndjson) in OpenSearch Dashboards
  • Adds OPA to the SIEM bootstrap job for import on every sync

Prerequisite: This link only has effect on OPA if the opa-otel link also exists. Without it, there is no OTEL sidecar to configure. On the OpenSearch side, this link works independently (SIEM resources are always created).

Cross-Stack (External) OpenSearch Support

This link supports exporting to an OpenSearch instance in a different stack/cluster.

Scenario Endpoint Port
Same stack (is_external: false) https://opensearch-cluster-master.{namespace}.svc.cluster.local 9200
External stack (is_external: true) https://{remote_host} 443

remote_host attribute: When the OpenSearch component is external (from another stack), the remote_host attribute on the OpenSearch component provides the FQDN/IP for cross-cluster access. This is typically an APISIX route or load balancer endpoint. Both cases use insecure_skip_verify: true for TLS.

OpenSearch Component Attributes Used

Attribute Source Usage
namespace REQ __opensearch.component.attributes.namespace Internal endpoint: opensearch-cluster-master.{ns}.svc.cluster.local:9200
admin_password REQ __opensearch.component.attributes.admin_password Authentication: basicauth/opensearch extension password
remote_host __opensearch.attributes.remote_host External endpoint FQDN (only when is_external: true)

Generated Sidecar Config (with OpenSearch link)

exporters:
  opensearch:
    http:
      endpoint: https://opensearch-cluster-master.opensearch.svc.cluster.local:9200
      tls:
        insecure_skip_verify: true
      auth:
        authenticator: basicauth/opensearch
    logs_index: opa

extensions:
  basicauth/opensearch:
    client_auth:
      username: admin
      password: {admin_password}

service:
  extensions: [basicauth/opensearch]
  pipelines:
    logs:
      receivers: [filelog]
      processors: [resource, attributes/cleanup]
      exporters: [opensearch]

What Gets Created on OpenSearch Side

When OpenSearch detects the opa-opensearch inbound link AND siem attribute is "true":

Resource File Description
Index Template siem/index-template-opa.json Mapping for opa-* index pattern
Alerting Monitor siem/alerting-opa.json opa-violation-events monitor for policy violation alerts
Dashboard siem/dashboards-opa.ndjson OpenSearch Dashboards saved objects (index pattern + visualizations + dashboard)
ISM Policy siem/ism-policy.json PCI DSS retention policy applied to opa-* indices

02 · The model

Four primitives.
Everything else is generated from them.

A stack is a directed graph. components own sub_components, carry attributes, and connect through typed links named source-destination. A link is not documentation — it emits env vars, secrets, routes, policies and monitoring on both ends.

06 · Compliance automation

Hundreds of controls.
Scanned continuously, evidenced automatically.

Compliance is not a document — it is the configuration surface plus the running cluster. Stacktic scans both: the Stacktic attribute layer for what is misconfigured, and live kubectl for what is actually true, including drift.

Names the fix The config scanner returns findings against the exact attribute to change — not "harden your gateway", but the attribute that generates that route.
Runtime, not presence PCI and ISO scans run real kubectl against the cluster and detect drift. Presence of a component is a plan, not proof.
Evidence into Git Results are written back and versioned with the stack — so the audit trail is a diff, not a screenshot taken the week before.
scanners run from the Stack Agent — on a schedule, or from a prompt
07 · The Stack Agent

Not a chat window
telling you it looks fine.

10 · The factory floor

Relations inside an application —
and between them.

Stacks link to other stacks. A database in one stack ships its metrics and logs to an observability stack in a different cluster, on a different cloud. Declared once, wired on both sides — not re-plumbed by hand every time either end changes.
